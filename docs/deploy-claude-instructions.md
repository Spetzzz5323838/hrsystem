# Інструкція для Claude Code: розгортання системи на бойовому сервері

Цей файл читає Claude Code, що працює **на бойовому сервері** (Windows Server 2019, без Docker). Власник проєкту — не програміст: пояснюй простою українською, що робиш і чому, перед кожним кроком, що змінює систему, питай підтвердження, після кроку кажи, як це перевірити.

## Жорсткі правила

1. Ти на **бойовому** сервері. Працюй лише з гілкою `master`. **Не змінюй код**, не роби коміти й push. Якщо щось у коді здається помилкою — зупинись і опиши власнику, що саме (він передасть розробнику).
2. **Ніколи не друкуй секрети** (токен бота, паролі, вміст `.env`) у відповідях, логах і повідомленнях. Якщо треба показати налаштування — показуй із замаскованими значеннями.
3. Секрети й дані, яких не знаєш, **питай у власника**, не вигадуй: токен Telegram-бота, `TELEGRAM_BOT_USERNAME`, пароль для бази, дані першого адміністратора (телефон, ПІБ, пароль від 10 символів), каталог встановлення, чи репозиторій приватний (тоді потрібен вхід у GitHub).
4. **`prisma db seed` — лише один раз і лише з `SEED_MODE=production`.** Без цього він створить тестових людей з паролем `Test1234!`. Ніколи не запускай `prisma migrate dev`, `migrate reset`, `db push` та нічого, що стирає базу.
5. Усі команди `prisma` — лише через `npx dotenv -e .env --` (без цього вони не бачать `DATABASE_URL`).
6. Не відкривай порт 3010 в інтернет. Система тільки для локальної мережі / VPN.
7. Перед будь-якою дією, що видаляє чи перезаписує дані (бекап-відновлення, перестворення бази), — отримай явне «так» від власника.

## Крок 0. Перевірка сервера

Перевір і покажи власнику таблицю «є / немає»:

- Node.js LTS не нижче 20: `node -v`, `npm -v`
- Git: `git --version`
- PostgreSQL 16 встановлений і служба запущена; `psql --version`, `pg_dump --version`
- PM2: `pm2 -v` (немає — `npm install -g pm2`)
- Порт 3010 вільний: `Get-NetTCPConnection -LocalPort 3010 -ErrorAction SilentlyContinue`

Чого немає — скажи, що встановити і де взяти (офіційні інсталятори nodejs.org, postgresql.org, git-scm.com). Встановлюй лише за згодою власника.

## Крок 1. База даних

За згодою власника, під користувачем `postgres`, створи користувача й базу (пароль придумай разом із власником або згенеруй і дай власнику записати; не показуй його в повідомленнях зайвий раз):

```
CREATE USER hruser WITH PASSWORD '<пароль>';
CREATE DATABASE hrsystem OWNER hruser;
\c hrsystem
GRANT ALL ON SCHEMA public TO hruser;
```

Перевір: `psql "postgresql://hruser:<пароль>@localhost:5432/hrsystem" -c "select 1"`.

## Крок 2. Код

```
git clone -b master https://github.com/Spetzzz5323838/hrsystem.git <каталог>
cd <каталог>
```

Якщо репозиторій приватний — попроси власника увійти (Git Credential Manager спитає сам) або дати токен доступу. Перевір `git branch --show-current` = `master`.

## Крок 3. Файл `.env`

Створи `.env` у корені проєкту за зразком `.env.example` (файл вже в проєкті). Обов'язкові значення:

```
DATABASE_URL="postgresql://hruser:<пароль>@localhost:5432/hrsystem?schema=public"
TELEGRAM_BOT_TOKEN="<токен нового бойового бота>"
TELEGRAM_BOT_USERNAME="<username бота без @>"
COOKIE_SECURE="false"
SEED_MODE="production"
INITIAL_ADMIN_PHONE="+380XXXXXXXXX"
INITIAL_ADMIN_NAME="<ПІБ>"
INITIAL_ADMIN_PASSWORD="<від 10 символів>"
```

- Бот має бути **окремий бойовий** (створюється в @BotFather); токен розробницького бота сюди не підставляти — два екземпляри з одним токеном конфліктують.
- `COOKIE_SECURE="false"`, поки сайт відкривається по http. Без цього вхід не працюватиме.
- `.env` не потрапляє в Git (він в `.gitignore`) — і не повинен.

## Крок 4. Встановлення, база, збірка

```
npm ci
npx dotenv -e .env -- npx prisma generate
npx dotenv -e .env -- npx prisma migrate deploy
npx dotenv -e .env -- npx prisma db seed
npm run build
```

Очікування: міграції — «All migrations have been successfully applied»; seed закінчується словом «Готово.» і **не** створює тестових людей; збірка завершується таблицею маршрутів без помилок. Якщо seed скаржиться на `INITIAL_ADMIN_*` — виправ `.env`.

Якщо міграція падає з помилкою доступу до схеми `public` — виконай `GRANT ALL ON SCHEMA public TO hruser;` у базі `hrsystem` і повтори.

## Крок 5. Запуск через PM2

```
pm2 start ecosystem.config.cjs
pm2 save
```

Перевір: `pm2 status` — `hr-web` і `hr-bot` у стані `online`; `pm2 logs --lines 30 --nostream` без помилок. Бот має вивести «Бота запущено (long polling)».

**Автозапуск після перезавантаження сервера.** Запропонуй власнику один із способів і виконай за згодою: завдання в Планувальнику завдань Windows «при запуску системи», яке виконує `pm2 resurrect` (від користувача, під яким стоїть PM2), або пакет `pm2-windows-startup`. Після налаштування запропонуй перезавантажити сервер і переконатися, що обидва процеси піднялись самі.

## Крок 6. Перевірка

1. З самого сервера: `Invoke-WebRequest http://localhost:3010/login -UseBasicParsing` → код 200.
2. З іншого комп'ютера в мережі (попроси власника): відкрити `http://<адреса сервера>:3010`. Не відкривається — перевір брандмауер Windows: правило «вхідні підключення», TCP 3010, лише для локальної мережі.
3. Власник входить під `INITIAL_ADMIN_*`. Має відкритись система. Якщо вхід «мовчить» — перевір `COOKIE_SECURE="false"` і перезапусти `pm2 restart all`.
4. Власник пише боту `/start` у Telegram — бот має відповісти.
5. Після успішного входу закоментуй у `.env` рядки `SEED_MODE`, `INITIAL_ADMIN_PHONE`, `INITIAL_ADMIN_NAME`, `INITIAL_ADMIN_PASSWORD` і виконай `pm2 restart all`. Повторне виконання seed більше не потрібне.

## Крок 7. Бекап (запропонуй власнику, виконай за згодою)

Щоденне завдання в Планувальнику завдань:
- `pg_dump --format=custom --file=<папка бекапів>\hrsystem-<дата>.dump "<DATABASE_URL без ?schema=...>"`;
- копія папки `storage\` проєкту (документи, матеріали, фото обходів) у ту ж папку бекапів;
- видалення копій старших за 30 днів.

Папку бекапів краще тримати **на іншому диску або іншій машині**, ніж база. Обговори з власником місце. Зроби один тестовий запуск і покажи, що файл створився.

## Крок 8. Звіт власнику

Коротко, без секретів: що встановлено, адреса системи, що перевірено й що ні, де лежать бекапи, що лишилось зробити власнику (створити справжні об'єкти й людей у «Структурі», налаштувати термінали на касових комп'ютерах за інструкцією на сторінці «Термінали»).

## Подальші оновлення

Оновлення робляться скриптом (він сам робить бекап, міграції, збірку й перезапуск):

```
powershell -ExecutionPolicy Bypass -File scripts\update.ps1
```

Що робити Claude Code під час оновлення: запусти скрипт, прочитай вивід, перекажи власнику «що нового» простою мовою (із `docs/updates.md`), чекай його «так». Якщо скрипт зупинився на помилці — **не імпровізуй** (не правь код, не роби `git reset`, не чіпай базу): покажи власнику текст помилки та команду відновлення, яку надрукував скрипт, і лише за його згодою виконуй її. Запис оновлення в `docs/updates.md` каже, чи потрібен seed; seed на живій базі — тільки якщо так і тільки з `SEED_MODE=production`.

## Типові проблеми

| Симптом | Причина й дія |
|---|---|
| Після входу знову просить увійти | `COOKIE_SECURE` не `false` при http; виправ `.env`, `pm2 restart all` |
| `Cannot resolve environment variable: DATABASE_URL` | команда `prisma` без `npx dotenv -e .env --` |
| Міграція: `permission denied for schema public` | `GRANT ALL ON SCHEMA public TO hruser;` у базі `hrsystem` |
| Бот: `409 Conflict` / «terminated by other getUpdates request» | той самий токен запущено ще десь (комп'ютер розробника); зупини там бота |
| Сайт не відкривається з інших комп'ютерів | брандмауер Windows, порт 3010 |
| Порт 3010 зайнятий | знайти процес `Get-NetTCPConnection -LocalPort 3010`; не вбивати без згоди власника |
| Після оновлення бот поводиться по-старому | `pm2 restart all` (обидва процеси) |
