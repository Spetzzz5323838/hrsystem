# Оцінювання персоналу: модель видимості, нагороди, квартальна оцінка — v1.3

---

## 1. Головний принцип: три різні шари, а не один рейтинг

Помилка, яку роблять майже всі подібні системи — змішують оперативні відмітки керівника й публічне визнання в одне число, а потім показують це число всім. Результат передбачуваний: працівники починають порівнювати бали, а не працювати, а адміністратор перестає ставити негатив, щоб не сваритися.

Розділяю на три шари з різною видимістю.

| Шар | Що це | Хто бачить | Навіщо |
|---|---|---|---|
| **Спостереження** | оперативні «позитив / негатив» із коментарем | автор, керівники вище, COO | інструмент керівника, робочі нотатки |
| **Визнання** | бейджі й номінації, тільки позитивні | усі | мотивація без приниження |
| **Оцінка** | квартальна за критеріями | сам працівник (після бесіди) і керівники | розвиток і зворотний зв'язок |

**Працівник ніколи не бачить ані окремих негативних відміток, ані свого числового рейтингу.** Число — внутрішній інструмент керівника. Працівник бачить рівень, бейджі й результат квартальної оцінки, який йому пояснили в розмові.

---

## 2. Шар 1: спостереження (закритий)

### 2.1 Як фіксується

Адміністратор обирає працівника, тисне «Позитив» або «Негатив», обирає привід із довідника й пише коментар. Три кліки, десять секунд. Довідник приводів:

| Позитив | Бали | Негатив | Бали |
|---|---|---|---|
| Викладка й порядок | +5 | Запізнення | −5 |
| Обслуговування клієнта | +5 | Порушення стандарту | −5 |
| Швидкість і темп | +5 | Помилка на касі | −8 |
| Санітарія і чистота | +5 | Санітарія | −8 |
| Ініціатива | +8 | Недбале ставлення до обладнання | −8 |
| Підміна, виручив зміну | +8 | Конфлікт з клієнтом | −10 |

Довідник редагується. Привід обов'язковий — він перетворює «мені не сподобалось» на факт, який можна обговорити.

### 2.2 Захист від зловживання

Оцінювання дає керівнику владу, і система має цю владу обмежувати:

| Правило | Навіщо |
|---|---|
| Коментар обов'язковий для будь-якого негативу | без факту це не оцінка, а настрій |
| Понад 2 негативи одному працівнику за тиждень — система просить зафіксувати, що бесіда відбулася | проблема не вирішується накопиченням відміток |
| 3 негативи поспіль без жодного позитиву → сповіщення директору кластера | це сигнал про пару «керівник–працівник», а не про працівника |
| Скасувати запис можна протягом 48 годин із причиною, редагувати — ніколи | історія не переписується заднім числом |
| Аналітика по авторах: хто ставить лише негатив, хто не ставить нічого, хто ставить усім однаково | оцінка керівника як керівника |
| Події старші 12 місяців не впливають на рівень | людина має право змінитися |

Остання колонка в аналітиці — найкорисніша. Адміністратор, який за квартал поставив 14 негативів і жодного позитиву, розповідає більше про себе, ніж про свій колектив.

## 3. Шар 2: визнання (відкритий)

Бейджі вирішують задачу мотивації без побічного ефекту заздрості. Ключова відмінність від рейтингової таблиці: **відсутність бейджа не читається як покарання**, тоді як останнє місце в списку — читається.

### 3.1 Автоматичні

Видаються системою за фактами, які вже в ній є. Ніякої суб'єктивності.

| Бейдж | Умова |
|---|---|
| Профіль закрито | усі компетенції посади чинні |
| Понад профіль | складено бонусні компетенції (пожежна безпека, правила торгівлі) |
| Швидкий старт | атестація з першого разу |
| Наставник | троє стажерів склали атестацію з першого разу |
| Без зауважень | півроку без негативних відміток |
| Завжди в строю | рік без жодного протермінованого документа чи компетенції |
| Стаж: рік · три роки · п'ять років | за датою прийому, з урахуванням перерв |

### 3.2 Номінації від керівництва

Ручні, з коментарем, публічні. Саме те, про що ви писали — «найкраща викладка».

- Найкраща викладка місяця
- Ініціатива кварталу
- Порятунок зміни
- Голос клієнта (подяка від покупця)
- Чистий цех

Обмеження, яке варто закласти: **не більше однієї номінації на місяць на об'єкт**. Якщо роздавати їх щотижня, вони знецінюються за квартал.

### 3.3 Рівні замість балів

Працівник бачить не число, а рівень. Це дає відчуття прогресу без матеріалу для порівняння.

| Рівень | Поріг |
|---|---|
| Новачок | 0 |
| Впевнений | 25 |
| Надійний | 60 |
| Опора команди | 120 |

Поріг рівня працівник бачить, свій точний бал — ні.

## 4. Шар 3: квартальна оцінка

Раз на квартал адміністратор заповнює форму з шести критеріїв, оцінка 1–5. Ваги налаштовуються по профілю посади: для касира вага обслуговування вища, для пекаря — якості й санітарії.

| Критерій | Що оцінюємо |
|---|---|
| Якість роботи | дотримання стандартів і технології |
| Надійність | графік, дисципліна, виконання домовленостей |
| Темп | продуктивність у звичайний і піковий день |
| Команда | взаємодія з колегами, готовність допомогти |
| Клієнт | ставлення до покупця |
| Ініціатива й розвиток | пропозиції, готовність вчитися, бонусні компетенції |

**Обов'язкова умова:** результат не публікується, доки керівник не зафіксував, що бесіда з працівником відбулася. Працівник підтверджує ознайомлення кнопкою в Telegram. Оцінка, яку людина побачила без розмови, працює проти мотивації.

Працівник бачить тільки свою оцінку й свою динаміку по кварталах. Порівняння з колегами немає ніде в інтерфейсі.

## 6. Чому не публічний рейтинг-таблиця

Спокуса зробити «топ-10 працівників місяця» велика, але:

1. Рейтинг на 10 позицій автоматично створює 90% тих, хто не в топі.
2. У різних відділах різні можливості заробити бали — касир бачить сто клієнтів на зміну, комірник жодного. Порівняння некоректне за побудовою.
3. Через два місяці люди починають працювати на метрику, а не на результат.

**Якщо потрібна змагальність — робити її командною**: магазин проти магазину, зміна проти зміни, за об'єктивними показниками (жодного протермінованого товару, всі медкнижки чинні, укомплектованість). Команда програє разом і не шукає винного всередині.

## 7. Модель даних

```prisma
model RatingEvent {
  id Int @id @default(autoincrement())
  personId Int
  type RatingType            // POSITIVE | NEGATIVE | REPRIMAND | AWARD | AUTO
  categoryCode String?       // привід із довідника
  points Int
  comment String?            // обов'язковий для NEGATIVE
  visibility Visibility      // PRIVATE | EMPLOYEE | PUBLIC
  authorId Int
  occurredAt DateTime
  cancelledAt DateTime?
  cancelReason String?
}

model RatingCategory {
  code String @id
  name String
  side RatingSide            // POS | NEG
  defaultPoints Int
  isActive Boolean @default(true)
}

model Badge {
  code String @id
  name String
  description String
  isAuto Boolean
  ruleJson Json?             // умова для автоматичних
}

model BadgeAward {
  id Int @id @default(autoincrement())
  personId Int
  badgeCode String
  awardedAt DateTime
  awardedById Int?           // null для автоматичних
  comment String?
}

model Review {
  id Int @id @default(autoincrement())
  personId Int
  period String              // 2026-Q3
  reviewerId Int
  scores Json                // {quality:4, reliability:5, ...}
  total Decimal
  discussedAt DateTime?      // без цього працівник не бачить
  acknowledgedAt DateTime?   // підтвердження в Telegram
}
```

## 8. Що додається в план

| Етап | Обсяг | Тижні |
|---|---|---|
| 4. Рейтинг і керівництво | журнал подій, довідник приводів, швидка панель, захист від зловживання | вже враховано |
| **+ Бейджі й номінації** | довідник, автоматичні правила, публічна вітрина досягнень | +1 |
| **+ Квартальна оцінка** | форма критеріїв з вагами, бесіда, підтвердження в боті, динаміка | +1,5 |
| **+ Аналітика оцінювання** | розподіл оцінок по авторах, сигнали про перекоси | +0,5 |

Разом етап 4 зростає з 2 до 5 тижнів. Бейджі можна запускати першими — вони найпростіші й дають ефект одразу.
