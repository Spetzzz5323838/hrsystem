# Облік робочого часу й обходи магазинів (v1.4)

Рішення власника від 2026-10-18. Реалізовано в 10 етапів. Джерело вимог: ТЗ «Система контролю робочих змін» + `notes.md`.

## Терміни

| Термін | Значення |
|---|---|
| Ділянка | частина магазину/цеху (Гастроном, Каси, Вхідна група). Не вузол оргдерева, окремий довідник |
| Тип ділянки | довідник мережі; ознаки «має бути персонал» і «загальна» (без закріплених працівників) |
| Регламент обходів | один на всю мережу, набір вимог, **версіонований** |
| Вимога | пункт регламенту: загальний стан / ділянка певного типу / кожен працівник певної посади; позначка «Щодня» |
| Обхід | щоденний (лише вимоги «Щодня») або щотижневий (усі вимоги) |
| Порушення | 🔴-оцінка завершеного обходу: відкрите → в роботі → усунуто |

## Облік робочого часу

- **Код працівника** (`Person.badgeCode`, 10 цифр) генерує система. Це штрихкод бейджа **і** пароль до каси: окремого пароля до каси немає. Штрихкод надсилається в Telegram при видачі й перевидачі (`lib/credentials.ts`, `lib/badgeCode.ts`).
- **Термінал** (`/terminal`): зареєстрований комп'ютер магазину (cookie `hr_terminal`, у базі лише хеш). Працюють старший касир і адмін. Касир підтверджує людину за фото й ПІБ. Прибуття/завершення визначає наявність відкритої зміни. Захист від подвійного сканування (10 с), підтвердження зміни коротшої за 30 хв.
- **Офлайн-черга**: якщо немає зв'язку, відмітки зберігаються в `localStorage` терміналу й відправляються автоматично (`/api/terminal/sync`, порядок за часом відмітки, ідемпотентність за `clientEventId`). Єдиний виняток із заборони localStorage.
- **Сигнал живості** раз на хвилину (`/api/terminal/heartbeat`). Термінал мовчить 3 дні → алерт сисадміну й COO (повтор через 3 дні).
- **Табель** (`/timesheet`): години по працівниках за місяць. Ручне виправлення/додавання зміни лише з причиною, пишеться в журнал.
- **Звіт по днях** (`/timesheet/report`, рішення 2026-10-19): рядок — працівник, стовпчик — календарний день, комірка — години за день, праворуч підсумок за період. Фільтри: період, підрозділ (будь-який вузол дерева з підлеглими), працівник (ПІБ). Рядки згруповані за підрозділом, у кожної групи підсумки. Зміна належить дню початку (нічна не ріжеться по півночі); працівник належить підрозділу своєї посади, а не магазину відмітки. Експорт в Excel (`/api/timesheet/report/export`) — ті самі фільтри; години в Excel числами (8,50). Права — `VIEW_TIMESHEET`. Код: `lib/timesheetReport.ts`.
- **Бот, «Відпрацьований час»**: кнопка головного меню й `/worktime` — години за поточний календарний місяць, лише свої. Головне меню (постійна клавіатура: відпрацьований час, задачі, новини, відпустка) показується прив'язаним до акаунта (`/link`, `/start`, `/menu`).
- **Автозакриття**: зміна відкрита понад 16 год → закривається тривалістю 6 год, позначка «автоматично», повідомлення адміну (щогодини).
- **Ділянки без персоналу**: через 30 хв після часу відкриття магазину — зведене повідомлення адміну про ділянки, де ніхто з відповідальних не відмітився (раз на добу). Дні тижня не враховуються.

## Обходи

1. **Регламент** (`/regulation`) — редагує сисадмін і COO. Збереження = нова версія, обхід фіксує версію при початку.
2. **Розклад** — по магазинах (щоденний час, щотижневий день+час): сисадмін, COO, директор кластера. Пропущений обхід (день минув, не розпочато) переноситься на наступний день на той самий час; повідомлення адміну, директору кластера, COO.
3. **Проведення** (`/inspections`, мобільний макет): 🟢🟡🔴; для 🔴 коментар обов'язковий; фото за потреби (стискається на телефоні, зберігається в `storage/inspections`). Завершити можна, лише коли оцінено все.
4. **Порушення** створюються при завершенні обходу. Для індивідуальної вимоги автоматично пишеться негатив «Порушення регламенту» (−5, лише керівникам, без правила «3-й негатив за тиждень»). Алерти з кнопкою «Прийнято в роботу» → «Усунуто»:
   - ділянка: відповідальні на зміні (нікого — усі відповідальні, немає — адмін);
   - індивідуальна вимога: сам працівник;
   - загальний стан: директор кластера, COO, адмін.
5. **Статистика** — секція «Обходи магазинів» в Аналітиці: лічильники 🟢🟡🔴, по магазинах і ділянках, найчастіше порушувані вимоги, порушення. Без KPI-формули й без розрізу по окремих працівниках.
6. **Фокус дня** — особисте повідомлення при прибутті на зміну, лише коли є що сказати: незакриті порушення по його ділянках/про нього та 🟡 з останнього обходу. Раз на добу, до 5 рядків, без балів і чужих оцінок.

## Права (можливості)

| Можливість | Хто |
|---|---|
| `OPERATE_TERMINAL` | старший касир (свій об'єкт), адмін |
| `MANAGE_TERMINALS` | сисадмін, директор кластера, COO |
| `VIEW_TIMESHEET` / `EDIT_SHIFTS` | адмін, директор кластера, COO; перегляд ще й бухгалтерія |
| `MANAGE_AREA_TYPES` | сисадмін, COO |
| `MANAGE_AREAS` | адмін свого магазину, директор кластера, COO |
| `MANAGE_REGULATION` | сисадмін, COO |
| `MANAGE_INSPECTION_SCHEDULE` | сисадмін, COO, директор кластера |
| `CONDUCT_INSPECTION` | адмін свого магазину, директор кластера, COO |

## Фонові задачі бота (pg-boss)

`shift-autoclose-check` (щогодини), `terminal-silence-check` (щогодини), `area-staffing-check` (кожні 10 хв), `inspection-schedule-tick` (кожні 10 хв), `badge-code-delivery`.

## Відомі обмеження

- Перевірка «ділянка без персоналу» не знає вихідних/свят магазину.
- Індивідуальні вимоги в обході беруть працівників на зміні; якщо в магазині ще ніхто не відмічається, — усіх чинних працівників посади.
- Офлайн: сторінку терміналу не можна відкрити вперше без зв'язку; накопичені відмітки не втрачаються.
- KPI-формула обходів відкладена.
